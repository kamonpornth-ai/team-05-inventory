### [Bug 1] เมธอด `sell_batch()` (บรรทัดที่ 421-427)
- **หมวดหมู่ / ระดับความรุนแรง:** `correctness` / `high`
- **ปัญหา:** ขาดคุณสมบัติความเป็นหนึ่งเดียว (Atomicity / Rollback) หากมีรายการใดรายการหนึ่งในชุดคำสั่งเกิดสต็อกไม่พอ รายการก่อนหน้าจะถูกหักสต็อกไปแล้ว ทำให้เกิดภาวะข้อมูลไม่สอดคล้องกัน (Partial Update)
- **กรณีที่ทำให้พัง:** สั่งซื้อสินค้า A (จำนวน 5 ชิ้น มีพอ) และสินค้า B (จำนวน 10 ชิ้น มีแค่ 3 ชิ้น) -> สินค้า A ถูกหักออกไป 5 ชิ้น แต่ฟังก์ชันพังที่สินค้า B โดยไม่มีการคืนค่าสต็อกสินค้า A
- **ข้อเสนอแนะในการแก้ไข:** ตรวจสอบยอดสต็อกของทุกรายการใน `orders` ให้ครบทั้งหมดก่อนเริ่มทำการตัดสต็อกจริง หรือใช้ Transaction Rollback mechanism

### [Bug 2] เมธอด `reserve()` (บรรทัดที่ 430-437)
- **หมวดหมู่ / ระดับความรุนแรง:** `correctness` / `medium`
- **ปัญหา:** เงื่อนไขการจองกับค่าที่ Return ไม่สอดคล้องกัน หากจำนวนที่ต้องการจองเกินกว่าสต็อกที่เหลือ บล็อก `if` จะไม่ทำงาน แต่ฟังก์ชันยังคง Return ค่า `item.quantity - self._reserved[name]` กลับไป ทำให้ผู้เรียกเข้าใจผิดว่าการจองสำเร็จ
- **กรณีที่ทำให้พัง:** สินค้าเหลือว่าง 2 ชิ้น แต่ส่ง `reserve(name, 5)` -> ระบบไม่ได้บันทึกการจองเพิ่ม แต่ Return ค่า `2` กลับไป ผู้ใช้เข้าใจว่าจองได้สำเร็จ
- **ข้อเสนอแนะในการแก้ไข:** ให้ raise `ValueError` หรือคืนค่า `False` / `None` เมื่อยอดจองเกินจำนวนที่มีอยู่จริง

### [Bug 3] เมธอด `items_in_price_range()` (บรรทัดที่ 439-446)
- **หมวดหมู่ / ระดับความรุนแรง:** `correctness` / `medium`
- **ปัญหา:** ขอบเขตช่วงราคาไม่รวมค่าที่จุดปลาย (Boundary Exclusion) โดย Docstring ระบุช่วงปิด `[low, high]` แต่โค้ดใช้เงื่อนไข `low < item.price < high` (ช่วงเปิด)
- **กรณีที่ทำให้พัง:** ค้นหาสินค้าช่วงราคา `100.0` ถึง `200.0` โดยมีสินค้าที่ราคา `100.0` หรือ `200.0` พอดี สินค้าเหล่านั้นจะตกหล่นไป ไม่แสดงในผลลัพธ์
- **ข้อเสนอแนะในการแก้ไข:** เปลี่ยนเงื่อนไขการเปรียบเทียบเป็น `low <= item.price <= high`

### [Bug 4] เมธอด `low_stock_report()` (บรรทัดที่ 448-455)
- **หมวดหมู่ / ระดับความรุนแรง:** `correctness` / `medium`
- **ปัญหา:** ไม่ตรงตาม Docstring ซึ่งระบุว่า *"ต่ำกว่าหรือเท่ากับเกณฑ์"* แต่โค้ดใช้ `< self.LOW_STOCK_THRESHOLD` (ขาดเครื่องหมายเท่ากับ)
- **กรณีที่ทำให้พัง:** สินค้ามีสต็อกเหลือ `5` ชิ้นพอดี (เกณฑ์คือ 5) สินค้านี้จะไม่ถูกรายงานเตือน
- **ข้อเสนอแนะในการแก้ไข:** เปลี่ยนเงื่อนไขเป็น `item.quantity <= self.LOW_STOCK_THRESHOLD`

### [Bug 5] เมธอด `concurrent_restock()` (บรรทัดที่ 457-463)
- **หมวดหมู่ / ระดับความรุนแรง:** `concurrency` / `high`
- **ปัญหา:** เกิดภาวะ Race Condition เนื่องจากมีการอ่านค่า `current` ไว้นอก Lock (`with self._lock:`) แล้วนำมาคำนวณและเขียนทับภายใน Lock
- **กรณีที่ทำให้พัง:** Thread A และ Thread B สั่งเติมสินค้าชิ้นเดียวกันพร้อมกัน (คนละ 10 ชิ้น จากเดิม 20) ทั้งคู่จะอ่านค่า `current = 20` ผลลัพธ์สุดท้ายจะกลายเป็น `30` แทนที่จะเป็น `40` (Lost Update)
- **ข้อเสนอแนะในการแก้ไข:** ย้ายบรรทัดการอ่านค่า `current` เข้าไปอยู่ภายในบล็อก `with self._lock:` ทั้งหมด

---

### [Bug 6] เมธอด `average_unit_value()` (บรรทัดที่ 465-470)
- **หมวดหมู่ / ระดับความรุนแรง:** `correctness` / `high`
- **ปัญหา:** มีความเสี่ยงต่อ `ZeroDivisionError` เมื่อคลังว่าง และตัวหารใช้ `len(_items)` ซึ่งเป็นจำนวนชนิดสินค้า (Item Types) แทนที่จะเป็นจำนวนชิ้นสินค้าทั้งหมด (Total Units) ตามความหมายของ Unit Value
- **กรณีที่ทำให้พัง:** คลังสินค้ายังไม่มีข้อมูล (`len == 0`) เรียกฟังก์ชันแล้วระบบ Crash ทันทีด้วย `ZeroDivisionError`
- **ข้อเสนอแนะในการแก้ไข:** ดักจับกรณี `len == 0` ให้คืนค่า `0.0` และเปลี่ยนตัวหารเป็นผลรวมของจำนวนชิ้นสินค้าทั้งหมด

# การเปรียบเทียบ Prompt Engineering เทียบกับ Context Engineering

## 1. การทดลอง 2 รอบ

### รอบที่ 1: การสั่งงานแบบ Prompt สั้น ๆ (ไม่มี Context)
- **Prompt:**
  > *"เขียน function ลด stock สำหรับระบบ inventory ให้หน่อย"*
- **ผลลัพธ์ที่ AI ให้มา:**
  AI เขียนฟังก์ชันลอย ๆ เช่น `def reduce_stock(item_id, qty)` ที่ไม่มีการเช็ค exception แบบของระบบเดิม ไม่รู้ว่าคลาสเดิมใช้ชื่ออะไร และไม่มีระบบป้องกันการตัดสต็อกเกินยอดคงเหลือ (ขาด Atomicity และ Data Validation)

---

### รอบที่ 2: การสั่งงานแบบมี Context ครบถ้วน (Context Engineering)
- **Prompt + Context:**
  > *"ปรับปรุงเมธอด sell() ของคลาส Inventory ด้านล่างให้รองรับการขายหลายรายการพร้อมกัน โดยแนบโค้ด inventory.py เดิมทั้งไฟล์*
  > 
  > *ข้อกำหนด:*
  > *- เพิ่มเมธอด sell_many(orders: dict[str, int]) -> dict[str, int]*
  > *- ต้องเป็น Atomic Transaction ถ้ามีรายการใดสต็อกไม่พอ ต้อง raise ValueError และ rollback ไม่หักรายการใดเลย*
  > *- ใช้ KeyError เมื่อไม่พบสินค้า และห้ามใช้ library ภายนอก"*
- **ผลลัพธ์ที่ AI ให้มา:**
  AI เขียนโค้ดที่ผสานเข้ากับคลาส `Inventory` เดิมได้อย่างไร้รอยต่อ มีการวนลูปตรวจสอบยอดสต็อกของทุกรายการก่อนตัดจริง และยกเลิกทั้งหมดหากพบข้อผิดพลาดตรงตามหลัก Atomicity

---

## 2. สรุปความแตกต่างและปัจจัยสำคัญ
1. **Prompt Engineering** คือการใช้คำสั่งที่ชัดเจนและระบุเป้าหมาย
2. **Context Engineering** คือการป้อนข้อมูลสภาพแวดล้อม กฎเกณฑ์ โค้ดเดิม และข้อจำกัดของระบบให้ AI รับรู้
3. **ผลลัพธ์:** การมี Context ครบถ้วนช่วยลดอาการ Hallucination ของ AI และทำให้โค้ดที่สร้างขึ้นตรงตาม Architecture เดิมโดยไม่ต้องเสียเวลาแก้ใหม่

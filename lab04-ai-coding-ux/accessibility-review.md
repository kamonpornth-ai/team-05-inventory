# ผลการตรวจ Accessibility และ Usability (Accessibility Review)

## 1. ตารางตรวจเช็กลิสต์ตามมาตรฐาน WCAG 2.1 ระดับ AA

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่แก้ไข / มาตรการรองรับ |
|---|:---:|---|
| ข้อความหลักสี `#111827` บนพื้นขาว มี contrast อย่างน้อย 4.5:1 | **ผ่าน** | ค่า Contrast Ratio อยู่ที่ **16.1:1** ผ่านเกณฑ์ WCAG AAA |
| ปุ่ม Primary (`#1E40AF`) มี contrast เพียงพอกับตัวอักษรสีขาว | **ผ่าน** | ค่า Contrast Ratio อยู่ที่ **8.2:1** ผ่านเกณฑ์ WCAG AA |
| ทุกช่องกรอกมี label ที่มองเห็นชัดเจน | **ผ่าน** | ใช้ Floating Label กำกับเหนือช่องกรอกเสมอ ไม่ใช้ Placeholder ลอยเดี่ยว |
| ช่องที่บังคับกรอกมีสัญลักษณ์ชัดเจน | **ผ่าน** | มีเครื่องหมายดอกจันสีแดง `*` กำกับที่ชื่อ Label |
| Error ไม่ได้ใช้สีอย่างเดียว มีไอคอนและข้อความด้วย | **ผ่าน** | ใช้ไอคอนเตือน ⚠️ คู่กับข้อความอธิบายวิธีแก้ไขที่เข้าใจง่าย |
| ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา | **ผ่าน** | จัดเรียง `tabindex` ตามลำดับสายตาอย่างเป็นธรรมชาติ |
| ปุ่มมีชื่อบอกหน้าที่ชัดเจน ไม่ใช่ OK หรือกากบาท | **ผ่าน** | ใช้ชื่อปุ่มชัดเจน เช่น `[ + บันทึกสินค้า ]`, `[ ยกเลิก ]` |

## 2. รายการจุดที่ AI ทำพลาดและเราได้ทำการแก้ไขเอง (อย่างน้อย 2 จุด)

1. **จุดที่ 1: การใช้ Placeholder แทน Persistent Label**
   - *สิ่งที่ AI ให้มา:* AI สร้างฟอร์มที่มีเฉพาะ `placeholder="กรอกชื่อสินค้า..."` โดยไม่มี `<label>` ด้านบน ทำให้เวลาผู้ใช้เริ่มพิมพ์ ตัวหนังสือ placeholder จะหายไป ผู้ใช้จะจำไม่ได้ว่าช่องนี้คืออะไร
   - *การแก้ไขของเรา:* เพิ่ม `<label>` ถาวรด้านบนของทุก input field เพื่อให้ผู้ใช้เห็นชื่อช่องตลอดเวลาแม้กำลังพิมพ์อยู่

2. **จุดที่ 2: การใช้สีเพียงอย่างเดียวในการสื่อความหมาย Error (Color-only Error State)**
   - *สิ่งที่ AI ให้มา:* AI เปลี่ยนเฉพาะสีกรอบกล่องข้อความเป็นสีแดงเมื่อเกิด Error โดยไม่มีไอคอนหรือข้อความช่วยเหลือ
   - *การแก้ไขของเรา:* เพิ่มไอคอนเตือน `⚠️` พร้อมข้อความ Inline Error Message ใต้ช่องกรอกที่อธิบายวิธีแก้ไขชัดเจน เช่น *"กรุณากรอกราคาต่อหน่วยเป็นตัวเลขที่มากกว่า 0"*
